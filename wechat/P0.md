# P0 — inventory and mini-program skeleton

LexiQuest stays the repo and the English name. New user-facing text in this directory uses 词境练习家. Nothing under `src/` or `desktop/` was renamed or rewritten.

Base commit: `acecfe1c71a2cf93d958170c00297d8e8f2582dc`.

This phase stops here. It does not start P1 through P6.

## What is in this directory

- `scene-inventory.md` — the 18 Phaser scenes: direct APIs, DOM and keyboard, and the touch replacement. Conclusions only.
- An ordinary mini program (not a mini-game project, not a web page): `app.json`, `app.js`, `app.wxss`, `sitemap.json`, `project.config.json`, and one page `pages/game/`.
- `pages/game/index.wxml` has a single `<canvas type="2d">`.
- `assets/atlas/skeleton-atlas.png` plus `skeleton-atlas.json` (frames `btn_up`, `btn_down`, `mark`).
- `assets/audio/tap.wav` (0.12s, 8 kHz, 16-bit mono PCM).
- One touch path: `bindtouchstart` → design-space hit test → the play target swaps atlas frame and calls `wx.createInnerAudioContext`, the reset target swaps back and stops the clip.
- `pages/game/layout.js` is the page’s scale and hit math. It is not `wechat/engine/`. That directory was not created.

`project.config.json` uses `compileType: miniprogram` and `appid: touristappid`. That AppID is the DevTools tourist id. It is not a registered WeChat application. Do not replace it, upload, or submit review from this branch.

## How to open it

This environment has no WeChat DevTools and no phone, so this page was not compiled or tapped on a mini-program runtime. Nothing below claims 跑通, a frame rate, a cold start, or a package-size acceptance result.

1. Install WeChat DevTools (stable). Do not register an app.
2. Import the `wechat/` directory as an ordinary mini program. Leave the AppID as tourist / 测试号 (`touristappid`).
3. Confirm the compile type is 小程序, not 小游戏. The page list is `pages/game/index`.
4. Compile and open that page. The canvas should letterbox a 1280×800 board. The title reads 词境练习家. Two atlas targets sit under it.
5. Tap the left target (terra `btn_up`). It should switch to `btn_down` and play `assets/audio/tap.wav`. Tap the green `mark` target. The left frame returns to `btn_up` and the clip stops.
6. Do not upload, and do not submit for review.

If the left frame changes but there is no sound, check the DevTools audio log. The page has no extra error sentence.

## Decisions for later phases

These are not implemented. The skeleton does not need them.

### Domain reuse and JSON loading

`src/domain` stays the source of rules, types, and copy branches. The web and Electron builds keep compiling it as they do now.

Runtime loads that a mini program cannot perform:

- `ensureChapterPlan` in `src/domain/chapter-plan.ts` is the runtime `fetch(new URL(..., import.meta.url))` of `chapters_v0.2.json` and `gloss_overlap_pairs_v0.2.json`. `installChapterPlan(chapters, gloss)` already accepts those two values. A later WeChat boot statically imports the two JSON files and calls `installChapterPlan`. It does not call `ensureChapterPlan`. Web boot keeps the fetch.
- Word lists in `src/domain/catalog.ts` are loaded with Vite `import.meta.glob("./data/**/*.json")`. Several other JSON files are already static ESM imports (`chapter_forest_v1.1.json`, spelling exclusions, title parts, forest rewards). Those imports are bundler syntax. The mini program does not execute them by adding a `require` of `src/domain` from this page.
- Later, a host shim feeds `mergeWordFiles` the same `WordFile` map. Build it with the TypeScript compiler already in the repo, or with a node script that writes a static import list. That is a build-time copy, not a new dependency. If a later phase wants a new package to do this, stop and ask before adding it.
- P0 does not import `src/domain` and does not add that shim. Changing the web glob or the fetch in this phase would touch the web build for no skeleton need.

### `host-copy` third branch

`shellCopy(desktop: boolean)` and `isDesktopShell()` stay the web/desktop split. `WEB_COPY` and `DESKTOP_COPY` stay byte for byte. `src/domain/host-copy.test.ts` locks those strings.

Later, add a WeChat copy object and `isWechatShell()` beside them, for wording differences only (where the save lives). Do not change combat, review, PIN, or wardrobe rules to fit the wording. Existing callers keep passing a boolean. WeChat call sites use the new branch. Do not fold WeChat into `isDesktopShell`, and do not rewrite the web or desktop sentences. Not added in P0.

### Compressed save fields and the quota prompt

`serialize` / `deserialize` in `src/domain/storage.ts` stay the verbose JSON used by `localStorage`. Keys in use today: `lexiquest.save.v1`, `lexiquest.profile.v1.*`, `lexiquest.profiles.v1`, `lexiquest.parent-pin.v1`. `ExamBattleScene` also touches `localStorage` directly. Parent PIN hashing stays `crypto.subtle` PBKDF2, and slot ids stay `crypto.randomUUID`, until the later platform phase. P0 does not polyfill either.

WeChat storage limits that do apply, unlike the package-size goals above: 1MB per key and 10MB total. Later, the storage adapter (not `serialize`) rewrites field names to short keys, writes that string with `wx.setStorage`, and measures UTF-8 bytes before the write. If one key would pass 1MB, or the total would pass 10MB, or `wx.setStorage` fails, the adapter keeps the previous value and shows a visible on-screen prompt. It does not trim the save and it does not drop spelling, PIN, profiles, wardrobe, or review fields. The prompt is later, when a save is actually written. The skeleton stores nothing.

Frames `btn_up` 88×88, `btn_down` 88×88, and `mark` 44×44 sit inside the image and are not empty. `tap.wav` is 1964 bytes, RIFF/WAVE, PCM, 8 kHz, mono. The whole `wechat/` tree is 39367 bytes. - Code files under `wechat/` have no `require("phaser")`, no `weapp-adapter`, and no `<web-view>`. There is no `wechat/engine/`. The word Phaser appears in inventory prose and in the adaptation comments the spec asks for.
