# P0 — inventory and mini-program skeleton

LexiQuest stays the repo and the English name. New user-facing text in this directory uses 词境练习家. Nothing under `src/` or `desktop/` was renamed or rewritten.

Base commit: `acecfe1c71a2cf93d958170c00297d8e8f2582dc`. P0.5 is a later patch on merged main `6e9e99d0c599262f053cc69395ea9d970d1b3a28` (PR #50). It still does not start P1.

## What is in this directory

- `scene-inventory.md` — the 18 Phaser scenes: direct APIs, DOM and keyboard, and the touch replacement. Conclusions only.
- An ordinary mini program (not a mini-game project, not a web page): `app.json`, `app.js`, `app.wxss`, `sitemap.json`, `project.config.json`, and one page `pages/game/`.
- `app.json` `window.pageOrientation` and `pages/game/index.json` `pageOrientation` are both `landscape`.
- `pages/game/index.wxml` has a single `<canvas type="2d">`.
- `assets/atlas/skeleton-atlas.png` plus `skeleton-atlas.json` (frames `btn_up`, `btn_down`, `mark`).
- `assets/audio/tap.wav` (0.12s, 8 kHz, 16-bit mono PCM).
- Touch path after P0.5: `bindtouchstart`, `bindtouchmove`, `bindtouchend`, and `bindtouchcancel`. One `changedTouches` identifier. The left target shows `btn_down` while pressed and plays `tap.wav` only on up-inside, then returns to `btn_up`. Moving more than 8 window logical pixels outside that target cancels with no audio. The right target still resets. `touchcancel` clears the press.
- `pages/game/layout.js` is the page’s scale, safe-area, and hit math. It is not `wechat/engine/`. That directory was not created.
- `p05-check.cjs` is a Node static/unit/layout check. `project.config.json` `packOptions.ignore` keeps it, and `p06-render.cjs`, out of the mini program package.
- P0.6: `app.json` `resizable` is a top-level `true` (not inside `window`, and not on the page). An end whose `changedTouches` lacks the tracked id clears the pointer only when `touches` is an array that also lacks it. A missing `touches` field does not clear, and the next start self-heals only when that start brings an explicit `touches` array. The page fallback does the same: present empty array clears, missing field does not. `x/y` without `clientX/clientY` is canvas-local and is not subtracted from the canvas rect. The debug line includes that source and is 14px. World art stays 1280×800 fit plus a 2048×800 cover; probe text and hits are logical pixels. The page still draws the P0.5 skeleton by default. A debug entry opened as `pages/game/index?p06=title|grade|battle` draws the three probe frames from the same `layout.js` numbers (`pages/game/probe.js`); it is opt-in, adds no engine and no atlas, and is not part of the release path. That entry has not been compiled in DevTools or run on a device.

`project.config.json` uses `compileType: miniprogram`. P0.6 sets `appid` to the supplied `wx63db876009dfe905`. Do not commit an AppSecret, and do not commit `project.private.config.json`. Do not upload or submit review from this branch.

## How to open it

This environment has no WeChat DevTools and no phone, so this page was not compiled or tapped on a mini-program runtime. Nothing below claims 跑通, a frame rate, a cold start, or a package-size acceptance result.

1. Install WeChat DevTools (stable). Do not register an app.
2. Import the `wechat/` directory as an ordinary mini program. The project AppID is the supplied `wx63db876009dfe905`.
3. Confirm the compile type is 小程序, not 小游戏. The page list is `pages/game/index`.
4. Compile and open that page. The canvas should letterbox a 1280×800 board. The title reads 词境练习家. Two atlas targets sit under it.
5. The page should open landscape. The 1280×800 board stays uniformly scaled, with letterbox on one axis only.
6. Press the left target. It should show `btn_down` while the finger is down, play `assets/audio/tap.wav` on release inside the target, and return to `btn_up`. Dragging more than 8 logical pixels outside cancels and does not play. The right target resets. A system touch cancel does not play.
7. Do not upload, and do not submit for review.

Atlas and audio failures are one red line on the canvas (`atlas load failed: …`, `audio: …`). A missing canvas node has no 2d context, so that one case cannot be drawn on the canvas. The page shows the native string `canvas node missing` in a `cover-view` instead. A missing 2d context uses the same native path with `canvas 2d context missing`. This is a review-needed deviation from “draw every failure on the canvas.” It was not checked in DevTools or on a device.

Non-release builds also draw one debug line: window size, dpr, backing store, scale and offset, the safe-area edges used for layout, frame names, the safe-area decision, and the canvas rect origin. `envVersion === "release"` is the only case that hides that line. The failure line stays. If `getAccountInfoSync` throws, the page does not treat that as release.

P0.5 was not run in WeChat DevTools or on a device. iOS safeArea axis correction is unverified on hardware. P0.5 acceptance is not passed. Node checks are not launch, touch, audio, FPS, cold start, or package-size proof.

Safe area: the page swaps `left/right` with `top/bottom` only when the reported rect overflows the current window and the swapped rect fits. `safeArea.right <= safeArea.bottom` is not the branch. A swap still marks the notch side uncertain, because `getWindowInfo` does not say which way the device rotated.

## Decisions for later phases

These are not implemented. The skeleton does not need them.

### Domain reuse and JSON loading

`src/domain` stays the source of rules, types, and copy branches. The web and Electron builds keep compiling it as they do now.

Runtime loads that a mini program cannot perform:

- `ensureChapterPlan` in `src/domain/chapter-plan.ts` is the runtime `fetch(new URL(..., import.meta.url))` of `chapters_v0.2.json` and `gloss_overlap_pairs_v0.2.json`. `installChapterPlan(chapters, gloss)` already accepts those two values. A later WeChat boot statically imports the two JSON files and calls `installChapterPlan`. It does not call `ensureChapterPlan`. Web boot keeps the fetch.
- Word lists in `src/domain/catalog.ts` are loaded with Vite `import.meta.glob("./data/**/*.json")`. Several other JSON files are already static ESM imports (`chapter_forest_v1.1.json`, spelling exclusions, title parts, forest rewards). Those imports are bundler syntax. The mini program does not execute them by adding a `require` of `src/domain` from this page.
- Later, a host shim feeds `mergeWordFiles` the same `WordFile` map. Build it with the TypeScript compiler already in the repo, or with a node script that writes a static import list. That is a build-time copy, not a new dependency. If a later phase wants a new package to do this, stop and ask before adding it.
- P0 does not import `src/domain` and does not add that shim. Changing the web glob or the fetch in this phase would touch the web build for no skeleton need.

### `host-copy` third branch

`shellCopy(desktop: boolean)` and `isDesktopShell()` stay the web/desktop split. `WEB_COPY` and `DESKTOP_COPY` stay byte for byte. `src/domain/host-copy.test.ts` locks those strings.

Later, add a WeChat copy object and `isWechatShell()` beside them, for wording differences only (where the save lives). Do not change combat, review, PIN, or wardrobe rules to fit the wording. Existing callers keep passing a boolean. WeChat call sites use the new branch. Do not fold WeChat into `isDesktopShell`, and do not rewrite the web or desktop sentences. Not added in P0.

### Compressed save fields and the quota prompt

`serialize` / `deserialize` in `src/domain/storage.ts` stay the verbose JSON used by `localStorage`. Keys in use today: `lexiquest.save.v1`, `lexiquest.profile.v1.*`, `lexiquest.profiles.v1`, `lexiquest.parent-pin.v1`. `ExamBattleScene` also touches `localStorage` directly. Parent PIN hashing stays `crypto.subtle` PBKDF2, and slot ids stay `crypto.randomUUID`, until the later platform phase. P0 does not polyfill either.

WeChat storage limits that do apply, unlike the package-size goals above: 1MB per key and 10MB total. Later, the storage adapter (not `serialize`) rewrites field names to short keys, writes that string with `wx.setStorage`, and measures UTF-8 bytes before the write. If one key would pass 1MB, or the total would pass 10MB, or `wx.setStorage` fails, the adapter keeps the previous value and shows a visible on-screen prompt. It does not trim the save and it does not drop spelling, PIN, profiles, wardrobe, or review fields. The prompt is later, when a save is actually written. The skeleton stores nothing.

DevTools `2.02.2609250`, base library `3.18.1` (the IDE reads `project.config.json`'s `3.5.5` but overrides it with `3.18.1` in the generated `project.private.config.json`), simulator `iPhone 12/13 (Pro)`, window `844×390`, DPR `3`, safeArea `47,0,797,369`.
