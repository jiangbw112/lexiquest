## 存储

| 键 | 作用 |
| --- | --- |
| `lexiquest.save.v1` | 迁移前的单档原文。迁移成功后不再写入。回退时按原文比对。 |
| `lexiquest.profiles.v1` | 角色名单，最多日常使用 6 个。名单坏了就不改任何角色文件。 |
| `lexiquest.profile.v1.<槽位>` | 该角色自己的一份 `SaveData`。学习、复习、词卡、通关、外观、年级、每日目标、一次性奖励标志都在这份里面。 |

家长 PIN 仍在 `lexiquest.parent-pin.v1`，全机一份。删除角色不能绕过它。

槽位 id 和存档里的 `profileId` 不是一回事。`profileId` 继续给称号和一次性奖励用。读入时如果 `profileId` 和已有角色相同，整次读入取消，不改已有角色。

## 迁移

1. 没有名单、且 `lexiquest.save.v1` 能读：先写入 `mig_` 加原文 SHA-256 前 16 位的角色文件，再写名单。成功后把迁移标成 `done`，记下原文 SHA-256。
2. 任一步写入失败：不写 `lexiquest.save.v1`。名单没写成时，下次启动用同一个槽位重试，不会变成第二个角色。
3. 原文读不了：不删原文，名单记下 `unreadable` 和当时的 SHA-256，不造空角色。原文以后若被修到能读，且 SHA 变了，下次再迁移。
4. 重启：迁移已完成则不再搬运。删掉该角色后也不会把原文自动装回来。
5. 回退：仅当原文 SHA 仍与记录一致时，卸下当时那个槽位并清掉迁移标记。其他角色保留。原文仍在，下次启动会再迁进同一个槽位。

## 会话

当前角色只活在内存里。每次启动先进入选择，不自动沿用上次。

写入必须同时满足：槽位里已有的 `profileId` 与这份数据相同，而且调用方记下的代次仍是当前代次。切换会增加代次并丢掉内存里的当前存档。考试场景记下自己的槽位键；代次已变时，不再把结果写进内存里的另一个角色。比较写入也只打在当初那个键上，键上的 `profileId` 不符就拒绝。

## 读入和删除

读入只追加。满 6 个、文件坏、`profileId` 冲突、或写入失败时，已有角色文件和原文都保持原样。写入名单失败时会删掉刚写下的新文件。

删除当前角色在「给家长」里，家长密码解锁之后，同一颗按钮再按一次才删。未解锁时函数直接返回。清掉这台电脑上的学习记录会清空全部槽位，但仍留下迁移标记和原文，避免原文在下次启动被装回来。
